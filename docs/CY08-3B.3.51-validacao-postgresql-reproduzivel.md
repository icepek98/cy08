## 6. Atomicidade, rollback e reexecução

- O roteiro SQL executado delimitou seus objetos por transação; `ROLLBACK` foi observado e a ausência de tabelas temporárias foi confirmada na mesma sessão.
- A migration 202611 **não contém `BEGIN`/`COMMIT`**. Foi comprovado que os comandos de criação e remoção podem ser revertidos quando o executor os envolve em transação explícita; isso não prova que qualquer runner de migrations faça esse envelopamento.
- No caminho de conflito real, `CREATE UNIQUE INDEX` falhou antes do `DROP INDEX`, preservando as linhas e o índice legado. Isso comprova o comportamento desse cenário específico, não atomicidade geral da migration sob qualquer tipo de falha.
- A migration **não é idempotente**: uma segunda execução após sucesso falha porque o índice canônico já existe. Não foi alterada para incluir idempotência.
